# Eye Fatigue Detection (EFD) 系統

## 1. 系統設計目的與架構
本系統為一款基於 **C++20** 的跨平台眼睛疲勞偵測與干預應用程式，核心目的為透過攝影機即時監測使用者的眼動特徵（包含 EAR 幾何特徵與非線性複雜度指標），評估疲勞程度，並適時發出提醒。此系統為純本地端運算（Edge Computing），保障個人隱私，同時內建 14 天科研實驗週期與數據同步管理。

系統採用分層架構，分為四個層級：
1. **表現與互動層 (UI Layer)**: 以 Qt6 為主的 GUI 框架，提供疲勞指示器 (HUD)、校準視窗與問卷系統。
2. **狀態與控制層**: 管理 20/5/5 防打擾狀態機、14 天實驗追蹤與平台生命週期切換。
3. **感知運算層**: 跨平台視訊擷取 (Camera HAL)、視覺推論引擎 (ONNX Runtime 468 點特徵定位) 及 EMD/MSE 分析。
4. **本機資料與同步層**: 原生 SQLite3 WAL 的本地資料庫，確保零資料遺失，並能在條件觸發下將結構化資料上傳至研究伺服器。

## 2. 系統主要功能
- **跨平台原生運作**: 支援 Windows (WinToast, Tray), macOS (Status Item, NSUserNotif), Android (Foreground Svc), iOS。
- **高精準即時偵測**: 基於 468 臉部特徵點模型計算雙眼 EAR（眼寬高比），支援動態適應基線技術，消除光線與視角改變影響。
- **多維度疲勞分析**: 結合 PERCLOS（閉眼比例）、異常眨眼頻率（幾何指標），以及 EMD (經驗模態分解) 和 MSE (多尺度熵) （非線性時間序列分析）。
- **20/5/5 智能防打擾**: 疲勞提醒觸發後進入 20 分鐘冷卻；期間每 5 分鐘進行輕量快篩；如離座 5 分鐘則自動清零基線。
- **14 天實驗門禁管理**: 自動追蹤實驗天數，第 14 天將強制鎖定進行後測問卷，填答後透過網路取得解鎖憑證。

## 3. 介面功能與設計目的
- **懸浮疲勞指示器 (HUD)**: 桌面常駐的置頂、半透明小視窗。透過顏色燈號（綠色：放鬆 / 黃色：注意 / 紅色：警告）讓用戶隨時感知自身疲勞狀態而不過度干擾。
- **自適應校準介面 (Calibration)**: 首次啟動引導使用者保持正常睜眼，建立個人的基礎 EAR 閾值。
- **實驗問卷門禁 (Gatekeeper)**: 在第 14 天實驗期滿時彈出並鎖死主介面，確保研究問卷的有效回收。
- **系統托盤與原生通知 (Tray & Notification)**: 常駐於系統角落，快速設定或暫停系統，並整合各作業系統的原生通知彈窗（如 WinToast），提供沉浸式提醒。

## 4. 眼動數據運作邏輯
1. **特徵萃取**: 從視訊幀中，取得 6 點眼部特徵，計算單眼/雙眼 EAR。
2. **閾值判定與自適應**: EAR 小於動態閾值 `m_currentThreshold` 即判定為閉眼。該閾值由使用者的清醒歷史（滑動窗口平均）結合光線變化不斷重新自我校正 (`AdaptiveBaseline`)。
3. **時間序列指標**:
   - `m_closedHistory` 累積閉眼狀態，由固定大小的窗口 (如 300 幀) 計算穩定比例 (PERCLOS)。
   - 記錄每次眨眼，判定眨眼總數與頻率。
4. **複雜度運算**: 每 15 幀更新一次 EAR 時序陣列，利用 EMD 與 MSE 進行信號分解，得出複雜度指數 (CI)。
5. **評分融合**: 將 PERCLOS (55%)、眨眼率 (25%)、複雜度 CI (20%) 依非線性邏輯換算為綜合疲勞分數 (0~100 分)。
6. **狀態轉移**: 若疲勞分大於 45 分（注意力提醒）或大於 65 分（嚴重警告），狀態機將推送警報並重置冷卻倒數。

## 5. 系統流程架構
1. **啟動階段**: 初始化 SQLite DB、相機驅動及 5-Thread 非同步管線引擎。進行生命週期事件綁定 (Sleep/Wake)。
2. **視覺管線**:
   - Camera Service -> `RawFrame` 取幀。
   - FaceLandmarker -> AI 推論定位 `landmarks`。
   - FeatureExtractor -> 計算幾何眼動特徵 (EAR/PERCLOS)。
3. **動態決策**: AdaptiveBaseline 修正閉眼判定閾值；EmdCalculator/MseCalculator 解析複雜度；FatigueStateMachine 更新 20/5/5 防打擾狀態。
4. **狀態反饋**: 觸發回呼函數 (`m_telemetryCallback`) 更新 UI (指標燈號、原生推播)。
5. **儲存同步**: 將批次資料存入 SQLite WAL；背景 `NetworkSyncWorker` 定時在適合網路環境下同步至中心伺服器，或於第 14 天執行鎖定與證書發放。
